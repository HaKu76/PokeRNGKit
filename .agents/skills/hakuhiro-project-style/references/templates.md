# Hakuhiro 项目模板

以下模板用于保持输出一致。删除不适用的段落和占位符；不要为了填满模板编造内容。

## 仓库描述

```text
<平台或对象> <产品/游戏> <具体用途>
```

名称待定项目：

```text
面向<对象>的<具体用途>（项目名称待定）
```

````markdown
# <项目名或直接结果>

<一句话说明目标对象、平台和结果。名称未定时明确标注。>

## 项目状态

<当前可用程度、阶段和最重要限制。>

## 功能范围

- <包含的能力>
- <明确不包含的能力>

## 使用方法

1. <最短可执行步骤>
2. <必要检查或结果>

## 原理或架构

<用可核验的接口、数据、偏移或流程说明实现。>

## 构建与测试

```bash
<真实可运行的命令>
```

<前置环境与实际验证结果。>

## 已验证版本

- 目标：`<平台/文件/浏览器>`
- 版本：`<精确版本>`
- 架构：`<架构>`
- SHA-256：`<实际校验值>`

## 已知限制与恢复

- <限制或未验证项>
- <备份、回滚或数据恢复边界>

## 许可与署名

<许可证、上游来源、修改关系和必要免责声明。>
````

## 提交信息

仅标题：

```text
<type>: <中文动作短语>
```

需要正文时：

```text
<type>: <中文动作短语>

原因：<为什么需要此变化>
影响：<兼容、迁移、数据或用户体验影响>
验证：<实际运行的命令与结果，或未运行原因>
```

示例：

```text
feat: 增加三代档案导入与导出
fix: 修复取消搜索后进度未清空问题
style: 优化移动端结果表格样式
chore: 更新 Vite 版本
docs: 补充 WebAssembly 验证记录
```

## 进度或更新日志

```markdown
## YYYY-MM-DD / vX.Y.Z

- 新增：<能力或交付物>
- 优化：<体验、性能或结构变化>
- 修复：<问题及修复后的行为>
- 更新：<依赖、文档、数据或版本>
- 移除：<删除内容及替代方案>
```

只保留本次实际存在的类别。

```text

```

Release 正文：

```markdown
## 本版本

- 优化：<体验或性能变化>
- 修复：<问题与修复结果>
```

## 构建元数据（推荐扩展）

字段只在值可由 Git、构建工具或产物核验时写入：

```json
{
  "version": "X.Y.Z",
  "gitCommit": "<full-commit-sha>",
  "gitTag": "vX.Y.Z",
  "buildDate": "YYYY-MM-DDTHH:mm:ssZ",
  "toolchain": {
    "node": "<exact-version>",
    "npm": "<exact-version>"
  },
  "artifacts": [
    {
      "file": "<artifact-name>",
      "target": "<platform-or-deployment-target>",
      "bytes": 0,
      "sha256": "<actual-sha256>"
    }
  ],
  "verification": {
    "commands": ["<command>"],
    "result": "passed"
  },
  "source": "<repository-and-tag-url>",
  "license": "<SPDX-identifier>"
}
```

## 版本建议（推荐扩展）

- 使用 SemVer：元数据写 `X.Y.Z`，Git tag 和 Release 标题写 `vX.Y.Z`。
- 未形成稳定兼容承诺时保持 `0.x`；新增能力提升 minor，向后兼容修复提升 patch。
- 稳定版本的破坏性变化提升 major，并在 Release 中给出迁移说明。
- 预发布使用 `-alpha.1`、`-beta.1`、`-rc.1`，不要用日期或模糊词代替版本。
- 只有准备实际发布时才更新版本；不要因普通提交自动改版本。
- 精确锁定构建工具链和发布二进制依赖；源码依赖采用精确版本还是兼容范围，服从项目自己的锁定策略并提交锁文件。
